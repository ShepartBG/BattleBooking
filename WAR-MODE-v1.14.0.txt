BattleBooking v1.14.0 — MOBILE + GAME EXPIRY + SUBSCRIPTION RENEWAL

FIXED
1) Mobile postponed-reason typing
   - Fixed the custom BattleBooking prompt remounting on every keystroke.
   - Cursor no longer jumps to the beginning; Bulgarian text types normally.

2) Mobile admin navigation
   - Owner navigation no longer squeezes all buttons into tiny squares.
   - Buttons keep readable width and the bottom navigation scrolls horizontally on small screens.

3) Public game visibility
   - Active and postponed games stay public only until exactly 4 hours after their scheduled date/time.
   - Time calculations now use Europe/Sofia wall-clock time instead of depending on the Vercel server timezone.
   - Old active/postponed rows are auto-closed.
   - Optional Supabase RPC + RLS migration included for DB-level enforcement.

4) Subscription renewal
   - New Owner action: "Поднови +30 дни".
   - Approve remains for first activation / free trial only.
   - Renewal adds 30 days after the current expiry if still active, otherwise 30 days from today.
   - Grace period is recalculated to +7 days after the new expiry.
   - Existing account/password are preserved.
   - Automatic professional renewal email is sent.
   - field_requests and organizers mirror are kept in sync when available.

5) Owner API security
   - field-request-status now requires an authenticated BattleBooking owner token.
   - Requests page now sends the owner Bearer token.

SUPABASE
Run this once in Supabase SQL Editor:
  supabase-battlebooking-v1.14.0-game-expiry.sql

NOTES
The application contains a JS fallback for game expiry, so it remains functional before the SQL migration is run. The SQL is still recommended because it enforces the same rule directly at database/RLS level.
